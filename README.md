# Panda - No-Code Pandas Workbench

Panda is a local-first data exploration application that exposes common pandas
analysis and data-visualization workflows through a desktop/browser interface.



## User Workflow

1. Upload a supported structured-data file.
2. Review its schema, missing values, duplicates, and inferred column roles.
3. Optionally filter rows, select columns, or choose a row range.
4. Run an analysis from the sidebar.
5. Inspect the result table, chart, context, and generated pandas code.
6. Export the selected dataset or result as CSV, Excel, or chart PNG.
7. In desktop mode, reopen or delete locally saved datasets.

All analysis endpoints apply the same selection pipeline before calculating a
result. This keeps tables, charts, and exports consistent with the user's active
row and column choices.

## Current Features

### Understand the dataset

- Overview and schema insights
- Data quality audit
- Column dictionary
- Head, tail, and reproducible sample previews
- Column profiler
- Missing-value analysis
- Value counts and percentages

### Analyze with pandas

- Group analysis with count, sum, mean, median, mode, min, max, standard
  deviation, variance, share, contribution, difference from average, and rank
- Contribution analysis
- Period-over-period variance analysis
- Group and segment comparison
- Time-series aggregation
- Pivot tables and crosstabs
- Top/bottom ranking
- Numeric distributions
- Outlier detection using IQR, z-score, MAD, or percentile thresholds
- Pearson, Spearman, and Kendall correlations

### Visualize

- Automatic chart recommendation
- Histogram and value-count bar
- Vertical, horizontal, and stacked bars
- Line, area, and combo charts
- Pie, donut, and treemap charts
- Boxplots, scatter plots with trend lines, and correlation heatmaps

Charts are calculated by pandas in the backend and returned as ECharts JSON
recipes. The browser renders those recipes; it does not recalculate the data.

## System Architecture

```text
Panda.vbs
   -> desktop.py (optional native pywebview shell)
      -> app.py (Flask routes, pandas calculations, exports)
         -> storage.py (CSV files + SQLite metadata)
      -> index.html (controls, API requests, tables, ECharts rendering)
```

### Request flow

```text
Upload
  -> parse and normalize with pandas
  -> save CSV and metadata
  -> store only the dataset ID in the Flask session
  -> reload the DataFrame for an API request
  -> apply selected columns, row filter, and row range
  -> calculate with pandas
  -> return JSON/table/chart recipe
  -> render or export in the UI
```

The Flask session stores a dataset ID, not a DataFrame. Dataset rows live in
`panda_data/datasets/` as normalized CSV files. SQLite stores names, dimensions,
column metadata, and timestamps. This design survives server restarts and avoids
placing large objects in cookies or global process memory.

## Codebase Map

| File | Responsibility |
| --- | --- |
| `app.py` | Upload parsing, shared selection logic, Flask endpoints, pandas calculations, chart recipes, and exports. |
| `index.html` | Single-page UI, operation controls, API calls, result tables, ECharts rendering, and client download actions. |
| `storage.py` | Dataset CSV persistence and SQLite metadata operations. Contains no analysis formulas. |
| `desktop.py` | Starts Flask on a free localhost port and hosts it in a pywebview window. |
| `Panda.vbs` | Silent Windows launcher that uses `.venv/Scripts/pythonw.exe`. |
| `smoke_workbench.py` | Fast representative API integration test. |
| `audit_all_features.py` | Deterministic, independent correctness audit for every active feature and chart mode. |
| `validation_random_dataset.csv` | Reproducible mixed-type fixture generated by the exhaustive audit. |

## Important Contracts

### Selection order

`app.py::apply_selection` applies operations in this order:

1. Keep selected columns.
2. Apply the requested row filter.
3. Apply the row range with pandas' end-exclusive `iloc[start:end]` behavior.

An endpoint must not apply this selection a second time. Shared selection logic
is the source of truth for analysis and export behavior.

### Missing values

Pandas-native missing-value behavior is preserved unless an operation needs an
explicit display category. Categorical summaries display missing values as
`(Missing)`. Numeric calculations ignore `NaN` using pandas defaults.

### Aggregations

Aggregation names are normalized and validated before they reach `groupby` or
`pivot_table`. Standard deviation and variance follow pandas sample-statistic
semantics. Contribution percentages use the grand total of non-missing metric
values as their denominator.

### Dates

Native datetime columns are accepted directly. Text columns are recommended as
dates only when at least 75% of a sample parses successfully. Time-series and
variance endpoints convert the selected date column explicitly before grouping.

### Errors

Invalid fields, unsupported file types, empty numeric selections, and impossible
operations return a JSON error with an HTTP 400 response. Missing sessions or
saved files return a clear dataset error instead of silently using other data.

## Running Locally

Panda targets Python 3.15. The current dependency set supports Python 3.11
through 3.15, but Python 3.15 is the recommended and tested runtime.

### Desktop application on Windows

```powershell
py -3.15 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-desktop.txt
```

Then double-click `Panda.vbs`, or run:

```powershell
python desktop.py
```

Run the install command again after pulling a version that changes either
requirements file. Parquet, Feather, Arrow, and ORC require PyArrow; legacy
`.xls` files require xlrd.

### Browser development server

```powershell
py -3.15 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Open the localhost URL printed by Flask. Set `PANDA_LOCAL_STORAGE=1` to expose
the saved-dataset manager used by desktop mode.

## Supported Uploads

- CSV, TSV, and delimited text
- JSON, JSON Lines, and NDJSON
- XLSX and XLS
- Parquet, Feather, Arrow, and ORC
- Gzip and Bzip2 compressed text
- ZIP archives containing a supported structured-data file

CSV encoding and delimiters are detected before pandas parsing. Compressed text
is decompressed before detection. A ZIP upload uses its first supported file.

## Verification

Run the fast integration smoke test while iterating:

```powershell
python smoke_workbench.py
```

Run the upload-format audit after changing readers, dependencies, or packaging:

```powershell
python audit_upload_formats.py
```

It creates representative CSV, TSV, text, JSON, JSON Lines, NDJSON, XLSX,
Parquet, Feather, Arrow IPC, ORC, Gzip, Bzip2, and ZIP payloads and sends each
through the real upload endpoint. It also verifies that the legacy XLS reader
is installed.

Run the exhaustive audit after changing formulas, selections, endpoint payloads,
charts, storage, or exports:

```powershell
python audit_all_features.py
```

The exhaustive audit builds a seeded dataset containing mixed types, missing
values, a duplicate row, and an extreme outlier. It independently recomputes
expected pandas results and currently checks 185 behaviors across uploads,
filters, analysis formulas, chart recipes, exports, and saved datasets.

## Contributor Guidelines

- Keep analytical calculations in `app.py`; keep `index.html` focused on input
  collection and rendering.
- Reuse `apply_selection` so operations honor filters consistently.
- Use pandas or NumPy operations rather than duplicating formulas in JavaScript.
- Return chart data as an ECharts recipe through the shared chart helpers.
- Add assertions to `audit_all_features.py` when a formula or API contract changes.
- Use `smoke_workbench.py` for quick wiring checks, not as proof of mathematical
  correctness.
- Do not commit `.venv`, `panda_data`, exports, uploaded datasets, or secrets.

## Privacy and Scope

Panda is designed for local exploratory analysis, not as a multi-tenant database
or permanent records system. Uploaded rows are persisted on the machine running
the app until the saved dataset is deleted. Review deployment storage and privacy
requirements before exposing an instance to untrusted users.
